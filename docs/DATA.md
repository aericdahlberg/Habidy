# DATA.md — Database & API

## Philosophy
Only build what the screens actually need. No future-proofing.
Add tables when you need them.

---

## Database Schema

> RLS is enabled on all tables. Server-side routes always use `adminClient()` to bypass RLS.
> Browser client (`supabase`) is only used client-side for reads that respect RLS.

### `users`
```sql
id                          uuid PRIMARY KEY DEFAULT gen_random_uuid()
new_user                    boolean DEFAULT true     -- false after onboarding completes
identity_statement          text                     -- "I want to be someone who..."
goal_category               text                     -- Health & Fitness | Career & Learning | etc.
friction_point              text                     -- biggest blocker from questionnaire
time_available              text                     -- energy time from questionnaire
display_name                text                     -- friendly name from onboarding profile
profile_name                text                     -- same as display_name (alias)
avatar_url                  text                     -- optional profile image URL
email                       text                     -- stored for friend lookup by email
engagement_mode             text CHECK (engagement_mode IN ('quick', 'guided', 'deep'))
google_calendar_connected   boolean DEFAULT false    -- true after OAuth + token store succeeds
last_coach_review_at        timestamptz              -- set by POST /api/agents/coach/apply; drives WeeklyReviewCard visibility
created_at                  timestamptz DEFAULT now()
```
> `new_user` checked at login: true → /welcome → /onboarding, false → /dashboard.
> `display_name` / `email` populated by `POST /api/onboarding` from profile screen data.
> `google_calendar_connected` is readable by the browser client via RLS — used by architect/page.tsx and profile/page.tsx to show/hide the calendar toggle and connection status.
> Run `supabase/social.sql` to add social columns if not already present.
> Run `supabase/migrations/20260506_google_calendar.sql` to add `google_calendar_connected` + `google_calendar_tokens` table.

### `google_calendar_tokens`
```sql
id              uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id         uuid REFERENCES users(id) ON DELETE CASCADE UNIQUE NOT NULL
access_token    text NOT NULL
refresh_token   text NOT NULL
expires_at      timestamptz NOT NULL    -- when the access token expires
updated_at      timestamptz DEFAULT now()
```
> RLS enabled; no client-readable policies — server-only via `adminClient()`.
> One row per user. Upserted on connect (`onConflict: 'user_id'`), deleted on disconnect.
> `access_token` refreshed automatically by `getValidAccessToken()` if within 5 min of expiry.
> On `invalid_grant` (user revoked in Google settings): tokens deleted, `google_calendar_connected` reset to false.
> Migration: `supabase/migrations/20260506_google_calendar.sql`

### `habits`
```sql
id                       uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id                  uuid REFERENCES users NOT NULL
habit_name               text NOT NULL            -- display name (column is habit_name, not name)
identity_label           text                     -- "I am a ___" — generated by Architect
cue                      text                     -- "After I make coffee, I will..."
craving                  text
action                   text
reward                   text
two_minute_version       text
category                 text                     -- Health & Fitness | Career & Learning | etc.
color                    text                     -- hex, optional
time_of_day              text DEFAULT 'anytime'
reminder_time            text                     -- morning|midday|afternoon|evening|late_night (null = use Architect suggested_time)
google_calendar_event_id text                     -- set after POST /api/calendar/habits succeeds
reminder_enabled         boolean DEFAULT true     -- per-habit reminder on/off
reminder_minutes_before  int[]                    -- e.g. {30,5}; null = inherit global default
difficulty_level         int DEFAULT 1            -- 1–5; incremented by Habit Coach on increase_difficulty proposals
last_rated_at            timestamptz              -- set when user submits weekly difficulty check-in
is_active                boolean DEFAULT true
created_at               timestamptz DEFAULT now()
```
> Category color is applied via CATEGORY_STYLES in HabitCard.tsx and architect/page.tsx.
> Migration: `supabase/migrations/20260507_reminder_prefs.sql`
> `difficulty_level` added by `supabase/migrations/20260508_habit_coach.sql`
> `last_rated_at` added by `supabase/migrations/20260530_difficulty_checkin.sql`

id                    uuid PRIMARY KEY DEFAULT gen_random_uuid()

### `habit_survey_responses`
```sql
id                uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id           uuid REFERENCES users NOT NULL
habit_id          uuid REFERENCES habits NOT NULL

went_right        text         -- free text, optional
went_wrong        text         -- free text, optional

```
> Populated when user swipes UP on a habit card (HabitCard.tsx survey sheet).

### `proposed_habits`

```
> Habits Architect suggested but user did not select.
> Surfaced in /add-habit when user hits 7-day streak on any habit.

### `conversation_memory`

id          uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id     uuid REFERENCES users NOT NULL

created_at  timestamptz DEFAULT now()
```
> Agent value is `'identity-gatherer'` (not `'constellation'`).

### `user_reflections`
```sql

user_id     uuid REFERENCES users NOT NULL

```

### `user_profile_context`
```sql
id          uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id     uuid REFERENCES users NOT NULL UNIQUE
summary     text             -- running AI-generated profile summary
updated_at  timestamptz DEFAULT now()
```
> One row per user. Updated after each reflection or survey via /api/explore.
> Read by all agents via getProfileContext(user_id).

### `tool_logs`
```sql
id          uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id     uuid
agent       text             -- agent name or 'session_end' marker
tool_name   text
input       jsonb
output      jsonb
success     boolean
error       text
duration_ms int
created_at  timestamptz DEFAULT now()
```

### `friendships`
```sql
id          uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id     uuid REFERENCES users(id) ON DELETE CASCADE NOT NULL
friend_id   uuid REFERENCES users(id) ON DELETE CASCADE NOT NULL
status      text CHECK (status IN ('pending', 'accepted')) DEFAULT 'pending'
created_at  timestamptz DEFAULT now()
UNIQUE(user_id, friend_id)
```
> RLS: users can read/write rows where they are user_id OR friend_id.
> Indexes on user_id, friend_id, and users.email for fast lookups.
> Migration: `supabase/social.sql`

### `habit_adjustments`
```sql
id              uuid PRIMARY KEY DEFAULT gen_random_uuid()
user_id         uuid REFERENCES users(id) ON DELETE CASCADE
habit_id        uuid REFERENCES habits(id) ON DELETE SET NULL  -- null if habit was deleted
adjustment_type text NOT NULL CHECK (adjustment_type IN (
                  'increase_difficulty', 'decrease_difficulty',
                  'shift_time', 'change_cue', 'flag_for_discussion'))
current_value   jsonb NOT NULL DEFAULT '{}'  -- snapshot before change: { value, habitName }
proposed_value  jsonb NOT NULL DEFAULT '{}'  -- what was applied:       { value, habitName }
status          text NOT NULL DEFAULT 'pending'
                  CHECK (status IN ('pending', 'accepted', 'rejected', 'dismissed'))
user_note       text    -- why the user rejected, if they explained
created_at      timestamptz DEFAULT now()
resolved_at     timestamptz  -- set when status changes from 'pending'
```
> Written by `POST /api/agents/coach/apply` for every accepted proposal (audit log).
> `status = 'accepted'` rows are read back by the Coach agent as `[PRIOR ADJUSTMENTS]` context.
> Indexes on `user_id` and `habit_id`.
> Migration: `supabase/migrations/20260508_habit_coach.sql`

## API Routes

### Auth (Supabase built-in)
Supabase Auth handles signup/login/logout via the client SDK.
Session stored via Supabase's built-in cookie mechanism (`@supabase/ssr`).
`user.id` from the Supabase session is used everywhere.

### Onboarding
```
POST  /api/onboarding
  Body: { identity_statement, goal_category, friction_point, time_available,
          user_id, email, profile_name, questionnaire }
  Saves: identity, goal, profile_name → users.display_name, email → users.email
  Sets: new_user = false
  Note: identity_statement is the only required field

POST  /api/mode
  Body: { mode: 'quick' | 'guided' | 'deep' }
  Auth: session cookie (getRouteUser)
  Saves: users.engagement_mode for the authenticated user
  Called by: /mode-select page on card tap (fire-and-forget)
```

### Habits
```
GET   /api/habits?user_id=           -- get user's active habits (is_active = true)
POST  /api/habits                    -- create habit(s) — accepts array
POST  /api/habits/[id]/log                      -- log completion or skip for today (upserts)
GET   /api/habits/[id]/streak                   -- returns current streak + last 7 days + phase
POST  /api/habits/[id]/difficulty-feedback      -- weekly check-in rating; returns { action: 'level_up' | 'keep' | 'scale_down' }
POST  /api/habits/survey                        -- save habit_survey_responses row
```

### Agents
```
POST  /api/agents/constellation      -- Identity Gatherer — POST messages, get reply
POST  /api/agents/architect          -- Architect — POST messages, get reply

POST  /api/agents/coach              -- Habit Coach — conversational weekly review (12 turns max)
  Body: { messages, userId, isFreestyleChat? }
  Returns: { message, proposalsReady?: CoachProposal[], turnsUsed, turnsRemaining }
  proposalsReady present only when Claude outputs COACH_PROPOSALS marker

POST  /api/agents/coach/analyze      -- Run weekly analysis without starting a conversation
  Body: { userId }
  Returns: { hasData: boolean, analysis?: WeeklyAnalysis, reason?: 'no_habits' }

POST  /api/agents/coach/apply        -- Apply accepted coach proposals to habits table
  Body: { userId, proposals: CoachProposal[] }
  Updates habits.habit_name | habits.time_of_day | habits.cue per adjustmentType
  Inserts habit_adjustments rows (audit log)
  Sets users.last_coach_review_at = now()
  Returns: { applied: string[] }  -- habit IDs that were updated
```

### Memory
```
GET   /api/memory/[agent]            -- get latest summary for this agent + user
POST  /api/memory/[agent]            -- save session summary
```

### Explore (Reflection)
```
POST  /api/explore
  Body: { userId, content }
  Saves: new user_reflections row
  Then: calls Claude to regenerate user_profile_context.summary
  Returns: { reflection, summary }
```

### Google Calendar OAuth
```
GET   /api/auth/google?from=onboarding|profile
  Auth: Supabase session cookie (getUser)
  Generates a randomUUID() nonce, stores as HttpOnly SameSite=Lax cookie (TTL 600s)
  Redirects to Google OAuth consent URL with state=nonce:from
  Scope: https://www.googleapis.com/auth/calendar.events only

GET   /api/auth/google/callback?code=&state=
  Verifies state nonce matches cookie (CSRF protection)
  Exchanges code for access+refresh tokens
  Calls storeTokens(userId) → google_calendar_tokens upsert + users.google_calendar_connected = true
  On success: from=onboarding → /onboarding/loading · from=profile → /profile?calendar=connected
  On any error: → /profile?calendar=error
  Clears nonce cookie after use
```

### Calendar
```
GET   /api/calendar/events
  Auth: Supabase session cookie
  Calls getValidAccessToken(userId) — refreshes if needed
  Fetches events for next 2 weeks from Google Calendar API
  Returns: { events: [{ title, start, end }], connected: boolean }
  Returns { connected: false } if tokens not found

POST  /api/calendar/habits
  Auth: Supabase session cookie
  Body: { habitName, cue, twoMinuteVersion, suggestedTime, userTimezone,
          identityLabel?, category?, habitId? }
  Creates a recurring daily RRULE event starting tomorrow in userTimezone
  Event title: {categoryEmoji} {habitName}
  Description: identity reinforcement, cue, two-min version, Log it link
  Reminders: per-habit reminder_minutes_before if habitId supplied, else global default [15, 0]
  suggestedTime: morning(7am) | midday(12pm) | afternoon(3pm) | evening(6pm) | late_night(9pm)
  If habitId given: writes google_calendar_event_id back to habits table
  Returns: { eventId } on success

PATCH /api/calendar/habits/[habitId]
  Auth: Supabase session cookie
  Body: { reminder_enabled?, reminder_minutes_before?: number[] | null, reminder_time?: string | null }
  Updates per-habit reminder prefs; propagates to Google Calendar event if connected
  reminder_minutes_before: null = revert to global default
  reminder_time: null = revert to Architect suggested_time
  Returns: { habit }

DELETE /api/calendar/disconnect
  Auth: Supabase session cookie
  Deletes google_calendar_tokens row
  Sets users.google_calendar_connected = false
  Returns: { ok: true }
```

### Profile
```
PATCH /api/profile/timezone
  Auth: Supabase session cookie
  Body: { timezone } — validated against Intl.supportedValuesOf('timeZone')
  Saves users.timezone; called fire-and-forget from useTimezoneSync hook on dashboard mount
  Returns: { ok: true }

GET   /api/profile/notification-prefs
  Auth: Supabase session cookie
  Returns: { prefs: NotificationPrefs }
  prefs shape: { email_reminder_enabled, auto_dismiss_when_logged, default_minutes_before: number[] }

PATCH /api/profile/notification-prefs
  Auth: Supabase session cookie
  Body: Partial<NotificationPrefs>
  Merges into existing prefs; propagates reminder changes to Calendar events
  that are currently inheriting the global default (reminder_minutes_before IS NULL)
  Returns: { prefs: NotificationPrefs, propagated: number }
```

### Social
```
GET   /api/social/friends?user_id=
  Returns: {
    friends: [{ friendship_id, friend_id, display_name, avatar_url,
                habits_today, completed_today, logged_today, completion_rate }],
    pending: [{ friendship_id, user_id, display_name }]
  }

POST  /api/social/friends/request
  Body: { user_id, email }
  Looks up target by users.email, creates pending friendship
  Returns: { friendship, display_name } or error

POST  /api/social/friends/respond
  Body: { user_id, friendship_id, action: 'accept' | 'decline' }
  Only the recipient (friend_id) can respond
  Accept: updates status to 'accepted'
  Decline: deletes the row
```

## Swipe Mechanic

| Gesture | Action |
|---------|--------|
| SwipeCheckIn (daily) | Framer Motion card stack — completes/skips each habit |
| Swipe right (HabitCard) | Complete — POST /api/habits/[id]/log with completed: true |
| Swipe left (HabitCard)  | Skip — POST /api/habits/[id]/log with completed: false |
| Swipe up (HabitCard)    | Open survey bottom sheet (3 questions), then POST /api/habits/survey |

SwipeCheckIn fires once per day (checked via `habidy_last_checkin` in localStorage).
